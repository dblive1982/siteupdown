Speed test

How fast is it?

Loads a page three times from our server and shows where the time goes: finding the server, connecting, securing the connection, waiting, and downloading.

What this speed test measures

The test loads the page you enter three times from our server and reports the middle result, so one slow moment does not skew the answer. It breaks the total into the stages every web request goes through, which shows you where the time is going rather than just how long it took.

  • Finding the server (DNS). Turning the name into an address. Slow DNS usually points to the domain’s name servers.
  • Connecting. Opening a connection to the server. This depends mostly on distance between us and the site.
  • Securing the connection (TLS). The HTTPS handshake that encrypts traffic.
  • Waiting for the first byte. How long the site takes to start replying. This is the best sign of how busy or slow the server or application is.
  • Downloading. How long the page itself takes to arrive, which grows with page weight.

How to read your grade

Under about 300 ms to the first byte is quick, 300 to 800 ms is fine for most sites, and above that it is worth looking at hosting, caching or heavy pages. Our measurement is from one data centre, so someone far away will see longer times. For a wider view use the outage map, which shows response times from places around the world, and read how to speed up your website and what is a good response time.

This is a server-side test of one page. It does not run scripts like a full browser lab test, so it will not match tools that measure rendering. Use it as a quick, honest first check.
